# Data Model

Postgres schema, created by `.migrations/*.ts` and typed in `libs/data/db/src/schema.ts`. Enumerations are defined once in code and enforced with `CHECK` constraints. Agency-scoped tables carry `agency_id` and use composite foreign keys `(agency_id, x)` so a row can only point at rows of the same agency.

## Tenancy and access

| Table                       | Holds                                                               |
| --------------------------- | ------------------------------------------------------------------- |
| `organizations`             | Customers                                                           |
| `agencies`                  | Billing tenants, each in one organization; SFTP import credentials  |
| `users`                     | Platform and organization users; `is_owner` for organization owners |
| `roles`, `role_permissions` | Custom roles per agency and their permissions                       |
| `memberships`               | One role per user per agency, tied to the same organization         |
| `invitations`               | Pending invitations (token hash, role, expiry)                      |
| `password_tokens`           | One-time password links                                             |

## Workflows

| Table                 | Holds                                                                                                                                                                                                             |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `graphs`              | One row per graph and scope: system (no agency) or agency; `role` (workflow, stage, rule)                                                                                                                         |
| `graph_versions`      | Immutable published versions and one draft per graph; `contract`, `dependencies`, `base_version_id`, `trigger` (generated from the start node)                                                                    |
| `workflow_runs`       | Runs, their state, status, parent links, leases and the user who started one by hand (`started_by_id`)                                                                                                            |
| `workflow_run_graphs` | The graph versions each run pinned at start                                                                                                                                                                       |
| `data_tables`         | Shared decision and lookup tables per scope, like `graphs`; `kind` (decide, lookup)                                                                                                                               |
| `data_table_versions` | Immutable published versions and one draft per table; `contract` (its fields), `base_version_id`                                                                                                                  |
| `workflow_run_tables` | The table versions each run pinned at start, one per key                                                                                                                                                          |
| `workflow_run_steps`  | Trace of every executed node                                                                                                                                                                                      |
| `signals`             | Counted signals runs wait on                                                                                                                                                                                      |
| `events`              | The outbox of workflow events: agency, type, payload, who caused it, when it was dispatched; encounter, claim and task changes write theirs by trigger                                                            |
| `event_runs`          | Which run an event started for each workflow (one per event and workflow)                                                                                                                                         |
| `schedule_runs`       | Which scheduled workflow already started for an agency on a day or month, so each fires once                                                                                                                      |
| `tasks`               | Human tasks, their queue, assignee (anyone who can open the agency: a member, an owner or platform staff; removing a member unassigns their tasks), due date, the permission needed to complete them, and outcome |

Triggers keep versions honest: a `base_version_id` points at a version of another graph (or table) with the same key, and every pin in `workflow_run_graphs` and `workflow_run_tables` points at a version of the graph or table its `key` names.

## Reference data

Reference data is cleaned once from its source into a gzipped TSV in `.seeds/data` and loaded by the base seed; nothing downloads it again. Each table holds one release: the seed truncates a table and loads its file, so a newer release drops rows the source no longer has, then analyzes the tables. Diagnoses are checked against the loaded ICD-10-CM year (FY2027, trips from 2026-10-01). Tables are named by source, keep only the columns something reads, and are indexed for the lookups that use them.

| Table                                       | File                                                      | What it holds                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `codes`                                     | `codes.tsv.gz`                                            | Every code set by `code_set`, with its description and whether it `is_billable`: ICD-10-CM FY2027 (billable codes plus the categories above them, which are not), ambulance HCPCS (A0021-A0999, active only) and HCPCS modifiers, CARC and RARC from X12, place of service, prescribable RxNorm, and the SNOMED CT codes the NEMSIS lists use. ICD-10 codes are stored without the dot. `code` is C-collated so code prefixes use the primary key; a trigram index serves description search |
| `nemsis_elements`                           | `nemsis-elements.tsv.gz`                                  | The name of every NEMSIS 3.4, 3.5.0 and 3.5.1 element                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `nemsis_codes`                              | `nemsis-codes.tsv.gz`                                     | The values NEMSIS itself enumerates, by element or attribute list (`@NV`, `@PN` and others)                                                                                                                                                                                                                                                                                                                                                                                                  |
| `nemsis_pick_lists`                         | `nemsis-pick-lists.tsv.gz`                                | Which `codes` each NEMSIS defined or suggested list (`PICK_LISTS`: impressions, symptoms, procedures, medications and others) offers; descriptions come from `codes`                                                                                                                                                                                                                                                                                                                         |
| `gnis_places`                               | `gnis-places.tsv.gz`                                      | USGS feature ID and name of every populated place, census place and town, for NEMSIS city codes                                                                                                                                                                                                                                                                                                                                                                                              |
| `geonames_postal_codes`                     | `geonames-postal-codes.tsv.gz`                            | City, state, county and coordinates of each ZIP code from GeoNames (CC BY 4.0: credit GeoNames wherever it is shown)                                                                                                                                                                                                                                                                                                                                                                         |
| `cms_zip_localities`, `cms_zip4_localities` | `cms-zip-localities.tsv.gz`, `cms-zip4-localities.tsv.gz` | Medicare carrier, locality and rurality of each ZIP for 2026 Q4, and the ZIP+4 ranges of split ZIPs that differ from their ZIP (a ZIP is flagged split only when it has such ranges)                                                                                                                                                                                                                                                                                                         |

`GET /api/codes` searches a code set (by code prefix or every word of the description, billable codes only, optionally within a NEMSIS pick list) or describes given codes, and the claim and import pages describe the codes they show from it. The CMS tables are loaded for the pricing and checks the next workflows bring back.

## Development workflow

Migrations are edited in place during development. `pnpm db:reset` drops `DB_NAME` and clones it from a reference database (`DB_REFERENCE_NAME`, `<DB_NAME>_reference` by default) that holds the schema and the reference data (code sets, NEMSIS, GNIS, GeoNames, CMS), with every billable ICD-10-CM description embedded (`codes.embedding`, an HNSW index) for Search Diagnoses. It rebuilds the reference database only when its fingerprint changes: a hash of the embedding model, the SQL the migrations send and the reference data files and their loaders, kept as the database's comment. Embeddings come from `EMBEDDINGS_URL` and are cached in `.cache/embeddings/<model>.bin` (git-ignored, about 300 MB) by a hash of each text, so a rebuild embeds only new or changed descriptions. It then publishes the billing graphs and tables and seeds the development organization with two agencies, built-in roles, the dev owner, and each agency's fees, payers, payer alias, facilities and billing profile. Restart `pnpm dev` after a reset, since it drops the database under the running apps. `pnpm db:migrate` and `pnpm db:seed` still migrate and seed a database in place, without dev data.

## Rules the database enforces

- A claim belongs to one encounter and one patient of its agency, and its origin and destination letters are both set or both empty.
- Claim lines have a HCPCS code, at most four two-character modifiers and positive units; claim diagnoses are ICD-10 codes, at most twelve.
- `tasks.permission` is one of the permissions in `libs/domain/access`.
